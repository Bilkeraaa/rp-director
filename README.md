# RP Director · 剧情导演

独立的 SillyTavern 前端扩展。在指定有效回合随正文模型检查剧情，自然选择继续当前情节、埋下线索或引入变化，无单独的模型请求。

## 安装

在酒馆「扩展 → 安装扩展」粘贴此仓库的 HTTPS 地址，安装完成后刷新页面，在扩展面板打开「RP Director · 剧情导演」。无需更换酒馆版本或重新部署。云端持久性取决于酒馆用户数据目录是否持久保存；建议安装到当前用户，不勾选全局安装。

## 功能

### 1.1.0 修正

- 把普通情感互动与具体剧情事件分开；只有新增的事实、机会、障碍、安排或实际后果才作为事件。
- 新事件报告须包含具体变化、可互动事项和本轮正文原句；插件检查原句存在、等级一致及相同事件描述的重复，不把核对结果冒充剧情质量保证。
- 主面板直接显示上次是新事件、仅铺垫、暂缓还是报告未通过。旧记录标明旧版自报，进度与聊天均保留。
- 多次没有新事件时加强推进提示。自动模式下未发生新事件会提前复查；关闭自动间隔可立即固定回合数。
- 修复手机主题把按钮挤成竖排的问题。

在酒馆扩展管理里更新本插件后刷新。看到标题旁 `1.1.0` 即加载新版本，不需要清空进度或重新部署。

- 进度条、累计回合和最近五次检查记录。
- 每个聊天独立保存进度，一键清空后从零累计，不删除聊天或其他扩展的数据。
- 默认八回合检查；模型可调整下一次间隔，也可固定间隔。
- 按世界时代、地域、社会环境、身份地位、人设及近期剧情选择事件。
- 事件等级上限、活跃度、NPC倾向、角色核心能力保护、照顾型互动和重大危机开关。
- 优先延续伏笔与旧事后果，使用来源类别和近期记录减少重复套路。
- 不重复累计开场白、续写、重生成。同一条用户消息的群聊回复只算一次。
- 状态缺失或无效时明确提示，并在两个有效回合后重试。

「下次回复检查」只安排检查，不会自行调用AI。「清空进度，重新累计」只影响当前聊天的导演记录。

## 兼容与验证

使用 `SillyTavern.getContext()`、prompt interceptor、消息事件和聊天元数据接口。按 SillyTavern 1.19.0 官方接口核对，通过八组逻辑测试及三十五项模拟上下文浏览器断言，尚未经真实模型端到端验证。

事件尺度与角色保护由提示词引导，并非对模型输出的强制过滤。检查回合有少量额外提示词与状态输出token。特殊正则若提前删除状态注释，面板会报告未收到有效状态。

无外部服务、无遥测、无新增API密钥。聊天内容只随酒馆原有的模型请求发送。
