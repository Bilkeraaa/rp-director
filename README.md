# RP Director · 剧情导演

独立的 SillyTavern 前端扩展。在指定有效回合随正文模型检查剧情，自然选择继续当前情节、埋下线索或引入变化，无单独的模型请求。

## 安装

在酒馆「扩展 → 安装扩展」粘贴此仓库的 HTTPS 地址，安装完成后刷新页面，在扩展面板打开「RP Director · 剧情导演」。无需更换酒馆版本或重新部署。云端持久性取决于酒馆用户数据目录是否持久保存；建议安装到当前用户，不勾选全局安装。

## 功能

### 1.2.1 报告读取修正

- 改用专用纯文本区块返回导演报告，避免依赖HTML注释；插件自动移除区块，仍兼容旧注释格式。
- 精简必填格式，允许省略版本号、来源和维度等辅助字段，兼容整数/布尔字符串与JSON代码框；不从正文猜测事件、不虚构缺失的前后局面、后续影响或原句证据。
- 区分没有标记、报告截断、编号不符、JSON错误、字段错误与内容未通过核对，保存不含正文的诊断原因。缺失字段保留既有短记忆，不自动清空。
- 连续失败按2、4、基础间隔（至少4）回合复查，旧的连续失败记录也适用；有效报告后恢复正常节奏，仍可手动安排下次检查。
- 保留1.2.0的剧情判断、角色主动、意外、进度与重置设计。

### 1.2.0 剧情局面与意外

- 从跨轮局面判断发展中、收尾、平淡或停滞，不把新动作、新细节或重复情绪自动当成推进。
- 已有事件优先内部发展：角色依自己的目标、顾虑和判断采取有效行动；不靠无关突发截断场景。
- 平淡或收尾后允许新事与意外：角色主动、他人自主行动、外部世界变化、旧事后果皆可。意外可以是机会或麻烦，惊喜程度不等于灾难程度；不使用固定事件清单。
- 比较此前局面、现在局面与后续影响；仅铺垫和暂缓不计为实质推进。连续停滞加强行动有效性，不自动增加灾难或强行改变关系。
- 当前剧情短记忆记录事项、角色目标、阻碍、待解决内容和上次实质变化。只在检查回合随同一条模型请求更新，无额外模型调用；检查之间仍由正常聊天上下文承接。
- 主面板显示判断、处理方式、来源、是否有意外，以及前后变化；最近五次报告可查正文原句。
- 原进度、设置、聊天保留，旧版记录标明不适用新版判定。短记忆随选中的回复版本重建，重生成、切换回复、删除与清空不会遗留另一版本的剧情状态。

在酒馆扩展管理里更新本插件后刷新。看到标题旁 `1.2.1` 即加载新版本，不需要清空进度或重新部署。首次新版检查建立短记忆，可点“下次回复检查”立即安排。

- 进度条、累计回合和最近五次检查记录。
- 每个聊天独立保存进度，一键清空后从零累计，不删除聊天或其他扩展的数据。
- 默认八回合检查；模型可调整下一次间隔，也可固定间隔。
- 按世界时代、地域、社会环境、身份地位、人设及近期剧情选择事件。
- 事件等级上限、活跃度、NPC倾向、角色核心能力保护、照顾型互动和重大危机开关。
- 优先延续伏笔与旧事后果，使用来源类别和近期记录减少重复套路。
- 不重复累计开场白、续写、重生成。同一条用户消息的群聊回复只算一次。
- 状态缺失或无效时明确提示，连续失败时逐步延长复查间隔。

「下次回复检查」只安排检查，不会自行调用AI。「清空进度，重新累计」只影响当前聊天的导演记录。

## 兼容与验证

使用 `SillyTavern.getContext()`、prompt interceptor、消息事件和聊天元数据接口。按 SillyTavern 1.19.0 官方接口核对，1.2.1 的报告读取、失败诊断、重试、短记忆回退、计数与事件交互通过 17 组 Node 逻辑测试及 26 项模拟 DOM 交互断言；尚未经真实模型端到端验证。可运行 `node --test core.test.mjs` 复现核心测试。

事件尺度、角色保护和语义上的推进由提示词引导，并非对模型输出的强制过滤。原句存在、字段完整和前后描述不同不保证语义上真的有推进；近义改写仍需模型结合正文识别。缺失或未通过的报告也不证明正文没有发展。检查回合有少量额外提示词与状态输出token。若模型省略报告，或其他处理在插件读取前删除报告，插件不能凭空恢复它；面板会显示缺失标记。

无外部服务、无遥测、无新增API密钥。聊天内容只随酒馆原有的模型请求发送。
